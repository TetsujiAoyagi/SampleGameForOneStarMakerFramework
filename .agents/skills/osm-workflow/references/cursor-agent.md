# cursor-agent CLI

> **適用範囲: cursor-agent へジョブを投げる側（計画・レビュー担当、および人間）。**
> プロセス全体は [osm-workflow](../SKILL.md)、リポジトリの構造・契約は `AGENTS.md`。Grok 系モデルに限る制約は `AGENTS.md` の常時契約に従う。

Cursor は GUI を開かなくてもヘッドレスで走らせられる。コマンド名は `agent`（`cursor-agent` も同じ）。シェルによっては PATH で解決できないので、その場合は実行環境のインストール先をフルパスで指定する:

```bash
agent --list-models     # モデル一覧
agent status            # 認証確認
```

| オプション | 意味 |
|---|---|
| `-p` | 非対話（スクリプト用）。全ツールにアクセスできる。編集させるジョブは承認プロンプトで止まらないよう `--force` とセットにする |
| `--mode=ask` | 質問応答の読み取り専用モード。**監査はこれで回す**（下記） |
| `--plan` | `--mode=plan` の短縮形。実装前に方針を決めるモードで、所見ではなく計画の作成に進む（下記） |
| `--trust` | 確認なしで workspace を信頼する。未信頼の workspace を `-p` で動かすときに付ける（下記） |
| `--force` / `--yolo` | 全許可。`-p` で編集させるなら必須 |
| `--model <id>` | `--list-models` の ID。Grok 系を明示する |
| `--workspace <path>` | 作業ディレクトリ |
| `--continue` / `--resume` | 前回セッションの継続（差し戻しを投げ直すときに使う） |
| `-w [name]` | `~/.cursor/worktrees/` に隔離した git worktree を作って作業させる |

**`-p --force` で編集させるときは worktree 隔離とセットにすること。** このリポジトリには git で復元できない手元の層（[3つの層](../../../../docs/README.md#3つの層)）があるので、誤編集の危険を下げるために隔離する。ただし `-w` は作業する checkout を分けるだけで、アクセス制限ではない。全許可のプロセスは同じユーザー権限で絶対パスから元の checkout や手元の層に触れられる。確実に守る必要があるなら、実行ユーザーや実行環境を分ける。

**読み取り専用モードの確認範囲（2026-11-08、CLI 2026.11.05、Grok 系の最小プローブ各 1 回）:** `--help` は `plan` / `ask` のどちらも read-only と説明している。ファイル作成とシェル実行を指示すると、どちらのモードでもファイルは作られなかった。ただしモデルが実行を控えただけで、ツールの呼び出しが拒否されるところまでは確認していない。`plan` は所見を返さず計画の作成に進んだ。読み取り専用を保証として扱う必要があるジョブは、書き込まれても困らない入力の写しを workspace にする。

`.cursor/rules/*.mdc` は cursor-agent から自動で読まれる。**`AGENTS.md` も読まれる**ので、そこに置いた内容は実装ジョブのコンテキストにも毎ターン乗る。

## コスト規律（厳守）

**cursor-agent は従量課金の外部サービス。使うこと自体は問題ないが、空振りしたときに闇雲に繰り返してはならない。** 無駄な再試行はそのまま請求になる。

- 空・異常が返ったら、次に撃つのは本番ではなく**数秒で終わる最小プローブ**。同じ重さの再実行は禁止
- **未検証の仮説のまま本番を回さない。** 仮説はプローブで潰してから本番
- 繰り返しが必要だと判断したら、その前に理由と回数を人間に伝える

2026-08-05 の実測（この規律が無かったために焼いた分）: 監査タスクを 4 回実行して成果ゼロが 3 回。判明している 1 回だけで cacheRead 574,208 / input 63,677 / output 13,899 トークン。

## 非対話実行の落とし穴（実測）

| 症状 | 実際の原因 | 対処 |
|---|---|---|
| 出力が空なのに exit 0 | `--output-format text` / `json` は中身が空でも `is_error: false` を返す。**失敗として検出できない** | **初回から `--output-format stream-json`** を使う |
| `json` の `result` が進捗ナレーションだけ | 最終回答が出力されず、分析が `thinking` イベントに留まったまま終了する | `stream-json` で全イベントを拾う |
| `Workspace Trust Required` で exit 1 | 未信頼の workspace を `-p` で動かした。stream-json ではなく案内文が出る | `--trust` を付ける。想定外の出力を見たら jsonl の**先頭**を確認する |
| プロンプトの後半が無視される | **複数行プロンプトは先頭行しか届かない** | 1 行に畳むか、ファイルに書いてパスを渡す |
| エージェントが結論を出さずに正常終了 | 論点を詰め込むと探索でターン予算を使い切る（実測: thinking 497 件・ツール呼び出し 92 回で可視出力は進捗 5 行のみ） | **1 ジョブの論点は 2 つまで。字数上限を課し、結論を先に書かせる** |
| `outputTokens` 0 の空応答 | 一過性 | 最小プローブで切り分けてから、プロンプトを短縮して **1 回だけ**撃ち直す |
| `git diff` が実行されない | 読み取り専用のジョブではシェルを当てにできない。`-p` は非対話なので承認を求められず黙って続行する | 差分を事前にファイル化して渡す。置き場はテスト出力と混ざらない git 管理外の一時ディレクトリ |

論点を 2 つに絞った軽いジョブは実際に機能した。**失敗の原因はモデルではなくジョブ設計。**
