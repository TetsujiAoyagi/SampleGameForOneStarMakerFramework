# Phase C': 独立監査

- 人間または AI が担当する。AI は新規セッションで開始する。発見 C と判定 C の結論、指摘、疑念候補、誘導的な説明を含まない blind audit bundle を読み、可変な HANDOFF 全文をそのまま入力にしない。
- 判定 C の判定証拠が揃った head でのみ開始する。高コスト証拠を分類したスライスでは、それ以前の C' を暫定 C' として GO 判定に使わず、高コスト証拠を加えた最終 C' を行う。同じテストを C' が重複実行することは必須にしない。
- blind audit bundle の構成は [レビュー証拠](review-evidence.md#phase-c-の-blind-audit-bundle) を正とする。B result や原記録へ発見 C の所見を転載して迂回しない。
- 1 巡目は全体を初見で監査し、2 巡目以降は前巡指摘の解消と修正差分を中心に監査する。受け取る裁定は C' 自身の前巡指摘への決定記録だけとする（[巡ごとの範囲](review-evidence.md#巡ごとの範囲)）。
- AI 担当のモデル相違条件、人間担当の確認記録と独立性の扱いは [Phase と HANDOFF](phases-and-handoff.md) に従う。人間の回答前に AI が PASS や完了を記録しない。
- 受け入れ条件だけでなく、契約違反、構造劣化、未検証の失敗経路、Phase C 自体の見落としを探す。
- 指摘を「凍結済み条件または常時契約への違反により現在の問いを阻害する欠陥」と「後続スライスの入力」に分け、[blocker の基準](phases-and-handoff.md#blocker-の基準) に従って根拠を記録する。後者を理由に現スライスの実装や受け入れ条件を自動拡張しない。
- 指摘、残存リスク、監査できなかった範囲、使用したモデルを HANDOFF の Phase C' 欄へ記録する。
