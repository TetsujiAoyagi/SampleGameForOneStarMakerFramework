# 32. アクセシビリティ入力自由度の低減（片腕）

> ステータス: **構想・契約固定（実装前）**（2026-08-21）
> [ARCHITECTURE.md](../../ARCHITECTURE.md) に戻る
> 関連: [30-accessibility-identity.md](30-accessibility-identity.md)、[31-accessibility-output-budget.md](31-accessibility-output-budget.md)、[07-09-services.md](07-09-services.md)

本章は **同時に要求する入力の自由度を落とす**。コードは書かない。
候補集合は [§30](30-accessibility-identity.md) の Focusable + Actionable。全盲向けの出力予算は [§31](31-accessibility-output-budget.md) であり、律速が逆なので混ぜない。

---

## 1. 一文

第二の手は作れない。プログラムにできることは、移動と視点とアクションを同時に要求しないことに落とすことである。

この層は pull モデルで足りる。プレイヤーが次の対象を訊き、1 操作で決める。世界が勝手に話し続ける必要は無い。

---

## 2. なぜ §30 から分けるか

全盲の律速は出力帯域（§31）。片腕の律速は入力の同時性。
同居させると、ほぼ方針だけで書ける片腕側が、契約の足りない全盲側と同じ準備度に見える。分ける。

§30 に残すのは 1 行だけである: **レジストリは Focusable + Actionable を候補集合として供給し、Hidden は除外する。**

---

## 3. 設計判断

| # | 決定 | 根拠 |
|---|---|---|
| D-1 | **上限は同時入力の自由度を落とすこと** | 手足は増やせない。「全部自動化」はプレイの主体を奪う |
| D-2 | **巡回 + 決定 1 ボタン** | 狙いと動作を同時にやらない。候補は §30 |
| D-3 | **入力プロファイル本体は InputManager** | [07-09-services.md](07-09-services.md) §8。Phase 2 未着手 |
| D-4 | **UI は初期フォーカスと Tab / 決定 / キャンセル** | コード操作必須にしない |
| D-5 | **アシスタントの代理実行は片腕の代替ではない** | 全盲側（§31 / AI）の任意機能。混ぜない |

### 却下

| 却下 | 理由 |
|---|---|
| 全部自動化 | D-1 |
| 全盲の読み上げキューで操作を代替する | 律速が違う。片腕は見えている前提がありうる |
| 候補集合を入力層が自前に持つ | §30 の名前と Flags を再発明することになる |

---

## 4. 手段

| 手段 | 効果 | 置き場所 |
|---|---|---|
| コード入力（移動 + 視点 + アクション同時）を禁止するプロファイル | 片手で足りる同時性 | InputManager |
| ホールドをトグルに | 押しっぱなし用の第二指を要求しない | InputManager |
| フルリマップ | マウスのみ / スティック + 肩ボタン等 | InputManager |
| Focusable + Actionable を巡回し、決定は 1 ボタン | 同時照準をやめる | 候補は §30。操作は InputManager |
| UI の初期フォーカスと Tab / 決定 / キャンセル | 画面を片手デバイスで閉じる | UISystem + §30 の UI 記述子 |

Hidden は巡回から除外。[§30](30-accessibility-identity.md) の `Hidden \| Focusable` は作者付け不備。

---

## 5. 今やらない

| 項目 | 理由 |
|---|---|
| 入力プロファイル / リマップ UI | InputManager 未着手 |
| ワールド巡回の実装 | §30 S-2 の候補集合が先 |
| UI の初期フォーカス配線 | 既存画面への適用は §30 S-2 の BindAccessible と同時でよいが、今はしない |
| 触覚ボタンの割り当て | 要求が無い |

---

## 6. 撤退ライン

1. 「全部自動化」に戻さない
2. 候補集合を入力層へコピーしない
3. 全盲の出力調停（§31）と入力プロファイルを一つの「アクセシビリティ設定」に畳んで、片方の未完がもう片方を止める構造にしない

同時性を落とす上限と、§30 からの候補供給は残す。
