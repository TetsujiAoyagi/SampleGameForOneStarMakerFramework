3. Program requirements frozen for S-4a
---------------------------------------

Runtime variant:

- AppConfig key is assets:sceneVariant. The production/default value is empty; development Whitebox is "Whitebox".
- Player precedence remains JSON < environment < command line. A value is resolved once during startup; changing it requires restarting Play Mode/player.
- Editor Play Mode uses the active profile stored in UserSettings through a runtime bridge.
- SceneDirector owns the resolved value and passes it to IAssetManagement.LoadSceneAsync instead of the current hard-coded empty string.
- SceneAssetDescription's existing requested-variant-to-default fallback remains unchanged, so default-only Lighting/Events payloads remain usable while Whitebox is selected.
- Build/developer profile WorldWhitebox contains both empty and Whitebox variants. Production must not contain Whitebox.

Companion policy:

- Config key is world:cellCompanionSet.
- Missing key defaults to Full. A present empty or unknown value is a startup error; there is no silent fallback.
- Full = Environment + Lighting + VFX + Events.
- Planner = Events only.
- Lighting = Environment + Lighting.
- VFX = Environment + Lighting + VFX.
- A companion driver enumerates each loaded Cell SceneResource.Children and filters by SampleGame role. It never derives a child identity from the parent identity.
- No companion Add may be issued before the parent Cell is Stable. In-flight Adds are deduplicated. If the parent leaves during Add, an orphaned child must be explicitly unloaded after Add completes.
- The driver's lifetime is the InGameSession scene. Parent recursive unload remains the normal child-unload path.

Identity independence:

- Cell runtime classification uses SceneResource.StreamByDistance rather than CellIdentity parsing.
- Bounds use SceneResource.Volume rather than an identity-derived coordinate.
- Cell-child classification is structural: a resource is a child of a streaming Cell resource.
- Role tokens may be recognized only to select a companion role. They may not be used to derive coordinates, bounds, parent ids, dictionary keys, or generated child ids.
- Framework Runtime remains unaware of season or SampleGame discipline names.

World Workspace:

- Selection dimensions are season, coordinate, and role.
- Level opens Full or Whitebox Cell.
- Environment opens Cell + Environment.
- Lighting opens Cell + Environment + season Lighting + optional cell Lighting.
- VFX opens Cell + Environment + season Lighting + optional cell VFX.
- Planner opens Whitebox Cell + optional Events.
- Missing optional Lighting/VFX/Events can be created only as one editor transaction that creates the .unity scene, creates its SceneResource, links parent/child, upserts the map, and registers Addressables.
- Environment is bulk-created in S-4b, not through this everyday creation flow.
- Workspace operations use Unity editor APIs, not YAML text editing.

6. A0 risks and open design questions
--------------------------------------

- Empty is a meaningful production variant, so an editor bridge must distinguish "active profile selected empty" from "no active profile"; null/empty semantics and precedence need an explicit API contract.
- Structural child classification needs one authoritative implementation that does not turn role tokens back into parent/coordinate derivation.
- The current coordinate tint in DemoCellScene/EnvironmentScene conflicts with identity independence. S-4a must settle whether to delete it now or introduce an authored binding without silently taking on S-4b content generation.
- The optional companion creation flow needs a concrete rollback boundary. AssetDatabase editing and currently private generator helpers must not leave orphan files, map entries, links, or Addressables entries on failure.
- The workspace must require an exact Whitebox Cell payload for Level/Planner instead of accepting SceneAssetDescription's runtime fallback and accidentally opening a Full scene.
- AbstractApplicationInitializer, SceneDirector.Loading, and the bulk generator already exceed the warning threshold. The design must keep new responsibilities in small files and make only narrow edits to these files.
- Public Framework API additions must be the minimum necessary. No SampleGame role enum or workspace contract may leak into OneStarMaker Runtime.
