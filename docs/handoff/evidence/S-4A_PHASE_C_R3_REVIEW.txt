Findings

1. High / semantic / unique — FAIL
   World Workspace recovery treats the transaction's own Generate rewrite as an external mutation.

   SceneResourceGenerator.Generate always rewrites the reserved SceneResource (identity, payload, parent, volume, StreamByDistance) and then SaveAssets. Execute checkpoints the stub resource fingerprint at CreateReservedResource, calls Generate, and only afterwards refreshes the journal fingerprint.

   If the Editor crashes (or the process is killed) after Generate returns and before RefreshGeneratedAssets saves the new fingerprint, VerifyOrCaptureAsset sees a matching GUID and a mismatched fingerprint and throws "Content ownership mismatch". Rollback never reaches a destructive barrier. The journal stays. Open/Create remain blocked. The official Rollback command cannot finish. The generated companion is left in place.

   This is not the frozen residual at HANDOFF:571 (manual external edit while pending). Generate is a transaction-owned dependent mutation. WW-9 requires a checkpoint before the next dependent mutation; WW-10 requires crash recovery via the same reverse operations. The create-before-checkpoint gap is recoverable because an empty fingerprint falls back to path + expected shape. The Generate-before-refresh gap is not: the stub fingerprint is already non-empty, and mismatch has no owned-shape fallback.

   Evidence:
   - unity/Assets/OneStarMaker/Scripts/Editor/SceneGraph/SceneResourceGenerator.cs:81-209
     (in-place SerializedObject rewrite + SaveAssets)
   - unity/Assets/SampleGame/DependOnAll/Editor/WorldAuthoring/WorldCompanionCreationTransaction.cs:83-92
     (CreateReservedResource checkpoint → Generate → RefreshGeneratedAssets, no fault point between)
   - unity/Assets/SampleGame/DependOnAll/Editor/WorldAuthoring/WorldCompanionOwnershipProof.cs:70-91
     (empty fingerprint → VerifyExpectedShape; non-empty mismatch → throw, no owned-shape fallback)
   - unity/Assets/OneStarMaker/Tests/Editor/WorldAuthoring/WorldCompanionCreationTransactionTests.cs:40-54
     (FaultInjector only at WorldCompanionMutationPoint values; Generated is after Refresh)
   - docs/handoff/evidence/S-4A_FROZEN_HANDOFF_53a9d97.md WW-9 / WW-10 / line 571

   Required action (stay inside the frozen transaction owner; do not reopen Phase A):
   - Do not treat a transaction-owned Generate rewrite as external mutation.
   - Practical repair: leave the resource fingerprint empty until the post-Generate refresh (scene / node / Addressables fingerprints can stay at creation time if Generate does not rewrite those files). A crash in the Generate→refresh window then uses the existing empty-fingerprint + VerifyExpectedShape path, which already accepts both the reserved stub and the generated leaf shape.
   - Keep the round-2 rule: once a post-Generate fingerprint is stored, a same-GUID content mismatch must still fail-closed and keep the journal.
   - Add a fault-injection seam between Generate and the journal fingerprint save, plus a recovery test that the same journal can finish rollback after that crash.
