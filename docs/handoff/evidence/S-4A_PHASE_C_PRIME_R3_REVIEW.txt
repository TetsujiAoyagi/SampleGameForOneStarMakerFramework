1. Findings
-----------

P2 / semantic — Editor Play Mode variant bridge is left null after BuildVariantProfileSceneVariantTests.

The frozen HANDOFF (A3, static-bridge contract) requires tests that touch SceneVariantRuntimeBridge.EditorSceneVariantResolver to restore the previous delegate in finally. BuildVariantProfileSceneVariantTests instead writes null in TearDown. SceneVariantResolver treats a null delegate as "no editor override" and returns the AppConfig value. After this fixture runs in a living Editor domain, InitializeOnLoad does not run again, so Play Mode no longer reads the active BuildVariantProfile until the next domain reload.

Failure scenario: Unity Editor is already open; WorldWhitebox is the active profile (SceneVariant "Whitebox"); the operator runs BuildVariantProfileSceneVariantTests (or the full EditMode suite) inside that Editor; TearDown sets EditorSceneVariantResolver to null; the operator then enters Play Mode without a domain reload. ResolveSceneVariant takes the UNITY_EDITOR branch but SceneVariantResolver.Resolve sees editorResolver == null and returns configuredValue, which is app-config.json "assets:sceneVariant" = "". Every SceneDirector Addressables load then requests the empty variant instead of Whitebox. Production Player and a fresh domain load are unaffected; batch `run-tests.ps1` exits Unity so it does not reproduce. This is test-isolation damage to the slice's primary Editor Play path, not a broken injector implementation.

Evidence:
