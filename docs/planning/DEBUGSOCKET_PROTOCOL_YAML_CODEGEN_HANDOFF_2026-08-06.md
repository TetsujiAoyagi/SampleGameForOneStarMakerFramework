## 0. 1分で把握

| 項目 | 内容 |
|---|---|
| 問題 | Unity と DebugStudio で MessagePack wire DTO が手動二重定義。コメントでも「手動同期」と明記。既に `DebugSocketMessageType` 12/13 でドリフト発生中 |
| 決定 | **中立 YAML を正本**にし、両側へ **MessagePack 用 C# を生成**する（案 B-lite） |
| wire | **当面 MessagePack + 既存 WebSocket framing を維持**。protobuf/gRPC へは移行しない |
| 将来口 | YAML は transport 非依存に保ち、後から protobuf/gRPC emitter を足せる形にする（確率は半々。今は作らない） |
| 非目標 | 内部 `TelemetryRecord` 共有、フォーマット刷新、gRPC 導入、Unity への CLI control 型混入 |

## 1. 確定方針

### 1.1 採用

```text
protocol/*.yaml          ← semantic contract の正本（transport 非依存）
        │
        ▼ codegen (C# / MessagePack emitter のみ、当面)
   ┌────┴────┐
   ▼         ▼
 Unity    DebugStudio.Contracts
 (生成DTO)  (生成DTO)
   │         │
   ▼         ▼
 手書き拡張  手書き拡張
 FromRecord  IgnoreMember / CLI 12/13
```

### 1.2 共有する / しない

| 対象 | 共有（YAML→生成） | 理由 |
|---|---|---|
| wire DTO（`*EnvelopeV1`, `*DtoV1`, payload） | ✅ | 二重定義の本体 |
| enums（`DebugSocketMessageType` の **Unity 共通値のみ**、capability、hierarchy/inspector flags 等） | ✅ | Key/値ドリフト防止 |
| framing helper の **契約定数**（schema version 既定値、message type 番号） | ✅ | 正本化 |
| `DebugSocketProtocol` 実装本体 | ❌ 当面手書きのまま両側残可。後続で共通化検討 | 挙動差分リスクを初回スコープから外す |
| Unity `FromRecord` / `FromPayload` | ❌ 手書き partial/mapper | 内部 Telemetry 依存 |
| DS `LogEnvelopeV1.Kind` (`[IgnoreMember]`) | ❌ 手書き partial | UI/schema 都合 |
| CLI `ControlCommand*` / message type 12/13 | ❌ YAML の **surfaces: debugstudio-cli** か別ファイル。Unity 出力に出さない | Unity enum 汚染防止 |
| `DebugSocketOptions`, `UnitySessionCorrelationContext` | ❌ | Unity 専用ランタイム |
| `TelemetryRecord` / `TelemetryPayload` | ❌ | ゼロアロ内部モデル。wire と分離維持 |

### 1.3 生成物の扱い

- **生成 C# はリポジトリに commit する**（Unity/CI が毎回 codegen 必須にならないようにする）
- CI で「YAML 変更後に再生成し、diff が空」を検証する
- 生成ファイル先頭に `// <auto-generated>` と「手編集禁止、YAML を直せ」を入れる

### 1.4 名前空間（初回決定）

生成 DTO の論理名は現行互換を優先する。

| 出力先 | namespace | 備考 |
|---|---|---|
| Unity | `OneStarMaker.Foundation.DebugSocket`（`LogEnvelopeV1` のみ現行どおり `OneStarMaker.Foundation.Logging`） | 参照書き換えを最小化 |
| DebugStudio | `DebugStudio.Contracts.Protocol` | 同上 |

将来 gRPC 用に中立 NS へ寄せる移行は **別エピック**。初回はやらない。

### 1.5 YAML 配置（提案・PROTO-01 で確定）

```text
protocol/debugsocket/
  meta.yaml                 # schema_version 方針、emitter 設定
  messages.yaml             # message type 番号（surfaces 付き）
  enums.yaml                # flags / capability 等
  envelopes/
    debug_socket_envelope.yaml
    log_envelope.yaml
    debug_telemetry_envelope.yaml
    debug_telemetry_payload.yaml
    ...（1 message/file 推奨）
  surfaces/
    unity.yaml              # Unity に出す型一覧
    debugstudio.yaml        # DS に出す型一覧（CLI 含む可）
```

ルートはリポジトリ直下 `protocol/` を推奨（`docs/` 配下にすると「文書」と誤認されやすい）。

## 5. YAML スキーマ案（PROTO-01 で確定・ここでは草案）

```yaml
# envelopes/debug_telemetry_payload.yaml （イメージ）
name: DebugTelemetryPayloadV1
kind: message
surfaces: [unity, debugstudio]
csharp:
  unity:
    namespace: OneStarMaker.Foundation.DebugSocket
    accessibility: public
    sealed: true
    partial: true   # FromPayload を手書き partial に置くため
  debugstudio:
    namespace: DebugStudio.Contracts.Protocol
    partial: true
fields:
  - id: 0
    name: Shape
    type: u8
  - id: 1
    name: TargetIdentity
    type: string
    optional: true
  # ...
encodings:
  messagepack:
    # id を Key にマップ。欠番・追加のみ許可、再利用禁止
    key_field: id
```

### 型システムの最小セット

| YAML type | C# | 注意 |
|---|---|---|
| `u8`/`i32`/`i64`/`f32`/`f64`/`bool`/`string` | 対応 CLR 型 | |
| `optional<T>` or `optional: true` | `T?` | 値型は nullable |
| `enum` / `flags` | enum | 数値を YAML で明示 |
| `bytes` | `byte[]` | envelope.Payload 用 |
| `message` 参照 | 他 YAML 型 | ネスト DTO |

**禁止:** YAML から UnityEngine 型や DS ViewModel 型を参照すること。

## 6. 全体を通した注意（全チケット共通）

1. **バイト互換が最優先。** リファクタや「きれいな型」への変更で Key / 既定値 / null 扱いを変えない。  
2. **MessagePackSerializerOptions.Standard を維持。** カスタム resolver 導入は別判断。  
3. **生成クラスは partial。** 側固有ロジックは必ず手書きファイルへ。  
4. **Unity `.meta` GUID を壊さない。** 同パスで中身置換。リネームが必要なら meta を追従させ、asmdef 参照を確認。  
5. **LogEnvelope の namespace 差**を emitter 設定で吸収する。無理に Unity 側 NS を動かさない。  
6. **message type 12/13 を Unity に出さない。** surfaces で制御。  
7. **gRPC/protobuf を同時にやらない。** 将来口は YAML の中立性だけ。  
8. **日本語コメント方針:** 手書き拡張・生成器・README には「なぜ」を残す。生成 DTO の冗長コメント複製は不要（YAML の description があれば emitter が短く出してよい）。  
9. **スコープクリープ禁止:** Elastic 連携、UI、transport inversion、マルチクライアントは触らない。  
10. **失敗時の退避:** 生成置換でテストが赤のまま進めない。PROTO-00 golden に戻れない変更はリバート。
