# SceneGraph を何の木として扱うか

日付: 2026-07-19

関連: [05-scene.md](../../unity/Assets/Docs/Architecture/05-scene.md), [11-scene-graph-editor.md](../../unity/Assets/Docs/Architecture/11-scene-graph-editor.md)

## 本当に問うべきだった問い

SceneGraph は「画面遷移の分類図」なのか、
それとも「ロード済みサービスを共有し、破棄時点も決めるスコープ木」なのか？

## 結論

SceneGraph は後者として設計する。

画面名の整理ではなく、寿命と Ready 状態を共有するスコープの木。

補足:

- 通常の画面切替（`SwitchScene`）では親はアンロードせず、兄弟だけを差し替える
- 親は「毎回まとめて生死する単位」というより、枝にいるあいだ居残る共有スコープ
- 親を明示的に降ろすときだけ、子孫も再帰的に降りる

## 含意

親にサービス初期化を置く設計は正しい。
ただし条件は一つ:

> 親が初期化するのは、その親のスコープに入った全ての子が必要とするものだけ。

親は「セッション契約」そのものではなく、
そのスコープで保証される Ready 状態のオーナー。

- DI: インスタンスの配線・所有関係
- Scene 親: そのサービスをいつ Initialize / Load して Ready にするか
- 子: 親の Ready を前提にする

この分担なら、分割初期化は SceneGraph に残る。
DAG や Requires リストは不要。

## Title 問題が示していること

```text
OutGame
├─ Title       … Auth 不要
└─ Home        … Auth 必要
```

問題は「親に Auth を置くと Title が巻き込まれる」ことではない。

本当の問題は:

> OutGame を Auth のスコープにしたいのに、Auth 不要の Title を同じスコープに入れている

## 解法

1. Auth が枝全体で必須なら、木を実態に合わせて切る
   - 例: `AuthenticatedSession` 配下に Home / Shop / Battle を置く
2. Auth が画面木をまたぐなら、SceneGraph から外してアプリサービスにする
   - 構築と初期化は別。必要時に遅延初期化してよい
3. 一部の子だけ違うなら、差はその子 / Bootstrap 側で吸収する

## 以後の判断基準

新しい初期化物が出たら「Graph に載せるか」ではなく、これを問う。

> この状態は、どの画面集合で必ず共有され、いつ無効化されるべきか？

| 答え | 置き場所 |
|---|---|
| その親の全子孫で必要。親を出たら不要 | 親 Scene がロード責務を持つ |
| 特定の子孫だけで必要 | もっと下の子 / Bootstrap Scene |
| 画面木をまたぐ。アプリ / アカウント単位 | アプリサービス。必要時に遅延初期化 |
| 複数枝で共有するが寿命が一致しない | 無理に SceneGraph に載せない |

## 捨てるべき前提 / 残す前提

捨てる:

> 画面の見た目上の分類と、サービスの寿命スコープは必ず同じ木にできる

残す:

> SceneGraph は Ready 状態を保証するスコープ木であり、親はスコープ全体の初期化責務を持てる
